### Tool bugfixes
- [x] **`batch` failed when invoked via `runScript{script:"batch"}`** — surfaced by `test:agent` (Haiku): every sub-command came back `BATCH_FAILED`. Root cause was a system inconsistency, not a bad model call: the model speaks `{script, parameters}` (the LLM tool API) while the bridge speaks `{command, args}` (the WS wire protocol), and the `{script,parameters}→{command,args}` translation only ran when batch was called as its dedicated tool — the `runScript`→batch path passed sub-commands through untranslated, so the JSX handler (reading `entry.command`) rejected all of them. Fixed in three layers:
    - [x] **#1 Single choke point** (`server/ai/src/agent/executeTool.ts`) — moved batch sub-command normalization out of `case 'batch'` into one idempotent `normalizeBatchCommands()` step that runs *after* the switch whenever the resolved `command === 'batch'`. Now translation happens no matter how batch was invoked (dedicated tool OR `runScript{script:'batch'}`); no entry path can bypass it. *(This also subsumes the original "detect runScript+script=batch" patch — it's now a structural guarantee, not a special case.)*
    - [x] **#2 Tightened the `runScript` enum** (`server/ai/src/tools/definitions.ts`) — `runScript`/batch-sub-command `script` field now uses `RUNSCRIPT_COMMANDS = COMMAND_NAMES.filter(n => n !== 'batch')`, so `batch` is reachable ONLY via its dedicated typed tool — the ambiguous path is no longer even offered to the model. `COMMAND_NAMES` left intact (catalog + drift guard unaffected); the two enum assertions in `definitions.test.ts` updated to expect "all commands except batch".
    - [x] **#3 Defensive JSX handler** (`server/ae-bridge/src/scripts/mcp-bridge.jsx`) — the `batch()` loop now reads `entry.command || entry.script` and `entry.args || entry.parameters`, so the AE-side executor accepts both shapes. Covers callers that bypass the agent entirely (e.g. an MCP `runScript{script:"batch"}` from Claude Code, or a direct bridge test). ⚠️ Needs `build:plugin` + `install-plugin` + panel reopen to take effect in AE (already rebuilt into `cep-extension/dist/`).
    - Verified: `cubic-ai` build clean, 49/49 unit tests pass (incl. rewritten enum tests), drift guard 72-in-sync. Re-run `test:agent` after reinstalling the panel to confirm the batch lands end-to-end.
